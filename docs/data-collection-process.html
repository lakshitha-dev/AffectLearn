AffectLearn — Data Collection Process

How affect data is captured from a participant and stored durably for research analysis.

As a participant studies a lesson, the app continuously senses their emotional state and records it — together with the learner’s own self-reports — as a stream of durable research events. This page describes that pipeline end to end.

1. The pipeline, stage by stage

1

Capture (browser)

While the learner reads, the browser collects three streams: behavioral signals (mouse, scroll, keystroke category, idle, timing), facial frames (only if the camera is on, read in memory), and self-reports (the one-click feeling at pause points).

2

Bundle & stream

Signals are bundled into a ~30-second window and sent over a single authenticated WebSocket (JWT in the connection). Self-reports and adaptation interactions are sent as they happen.

3

Agent loop (backend)

The WebSocket handler runs the LangGraph agent: the Behavioral Bi-LSTM and Facial CNN-LSTM classify affect, late fusion combines them, the learner profiler updates, and in Phase B the pedagogical agent may return an adaptation to the browser.

4

Emit research event

Every classification, interaction, and self-report is passed to research_logger.emit() — one event per occurrence, stamped with a monotonic per-session sequence_number.

5

Buffer in Redis

Events are appended to a Redis stream (best-effort, non-blocking) so the learner’s session is never slowed by the database.

6

Drain to PostgreSQL

A background worker continuously drains the stream and batch-inserts into the durable research_events table. End-to-end latency is a few seconds (it is a research store, not a live feed).

3. What is collected

The durable store, research_events, holds these event types:

  • behavioral_affect_detected · facial_affect_detected · multimodal_affect_detected
  • self_report (ground truth) · adaptation_interaction · learner_profile_updated

Every row carries:

FieldMeaning
event_typewhich event (one of the above)
affect_state + probabilitiespredicted label + probability over {engaged, bored, confused, frustrated}
confidence, detection_modemodel confidence; behavioral_only / facial / multimodal
learner_id, session_id, cycle_numberwho, which session, which 30-s cycle
timestamp, sequence_numberwhen; monotonic per session (lets analysts detect dropped events — NFR23)
phase, groupstudy phase (A / B) and cohort (control / adaptive)
payloadevent-specific detail (e.g. self-report value, adaptation type)

Written directly to PostgreSQL (not via the stream)

Onboarding and study-config data are written straight to their own tables: users (consent, webcam choice) · questionnaire_responses · survey_responses · study_groups · study_phase · section_progress (time-on-section, affect states).

4. Durability & reliability

  • Decoupled writes. The learner’s real-time loop only touches Redis; PostgreSQL is filled asynchronously by the worker, so a slow database never affects the session.
  • Gap detection. Each event has a monotonic sequence_number per session, so analysts can verify no events were lost.
  • Requires Redis. The durable copy reaches PostgreSQL only through the Redis → worker path — Redis must be deployed and reachable for collection to work.
  • Latency. A few seconds from capture to a row in PostgreSQL — fine for a research store; a live dashboard should not expect instant rows.

5. Privacy

  • No video is ever stored — webcam frames are processed in memory and discarded.
  • Keystroke content is never captured — only the category of a keypress (e.g. alphanumeric / backspace).
  • Consent is required before any capture; participants may choose behavioral-only (camera off).

6. Verification (live end-to-end test)

Confirmed on the production deployment: a simulated participant session logged in, opened the WebSocket, streamed behavioral windows, and the events were verified in PostgreSQL:

  • WebSocket auth + handshake succeeded.
  • behavioral_window cycles ran the Bi-LSTM and persisted behavioral_affect_detected rows.
  • self_report persisted; the full agent graph ran (learner_profile_updated).
  • phase / group columns were populated; test rows were cleaned up afterwards.

Note: the behavioral model is currently a demo-grade artifact — the self-reports are the trustworthy ground-truth signal.
